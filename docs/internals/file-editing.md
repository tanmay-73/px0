# File Editing & File Operations

Implementation notes for in-browser editing. User-facing behavior is in [Direct File Editing](../features/file-editing.md).

## 1. Endpoints

Writes resolve paths through `safePath`, so paths outside the workspace are rejected. `/api/file/text` and `/api/file/stat` use `resolvePath`, which also admits an external file a language server named as a definition target (see [LSP](lsp-and-intelligence.md)). Every endpoint that writes (`/api/file/save`, `/api/fs/new`, `/api/fs/rename`, `/api/fs/delete`) requires a same-origin `POST` (`localPost`, the same check the git and LSP installer endpoints use; see [Architecture §5](architecture.md#5-security-model--path-sandboxing)).

| Endpoint | Request | Behavior |
| :--- | :--- | :--- |
| `/api/file/text` | `GET ?path=` | The file whole, for an editor: `{path, text, size, mtime, binary, tooLarge, eol}`. `text` is the exact bytes (no CRLF normalisation, so saving it back round-trips). `mtime` is unix milliseconds. `eol` is `"\r\n"` when the first line break is CRLF, else `"\n"`. `binary` is set (and `text` empty) when the first 8000 bytes contain a NUL or the file is not valid UTF-8, which a JSON string can't carry. `tooLarge` is set (and `text` empty) above 20 MB (`maxTextBytes`). `404` if missing, `400` for a directory. The file is stat'ed before it is read, so a write racing the read leaves an older `mtime` and the next save reports a conflict. |
| `/api/file/save` | `POST {path, content, mtime?}` | When `mtime` is given and the file exists with a different mtime, nothing is written: `409 {"error": "the file changed on disk", "conflict": true, "mtime": <current>}`. Otherwise creates missing parent directories, refuses a directory target, writes the file (`0644`). Then `Evict` drops the server's highlight cache entry, the LSP document is closed and open documents refreshed, the index is updated (`TouchPath`), and the git watcher is triggered; saving a file that did not exist also emits a `tree` event. Returns `{ok, path, size, mtime}`. |
| `/api/file/stat` | `POST {paths: [...]}` | `{files: {"<path as sent>": {exists, mtime, size, dir?}}, truncated}`, so an editor can notice open files changing on disk. A missing file is `{exists: false}`. At most 500 paths are checked (`maxStatPaths`); the rest are dropped and `truncated` is `true`. Paths outside the workspace (other than such admitted external files) are left out. |
| `/api/fs/new` | `POST {path, type}` | `type` is `file` or `dir`. Returns `409` if the path exists. Creates parents, writes an empty file or the directory, updates the index, triggers the git watcher, emits `tree`. Returns `{ok, path, type}`. |
| `/api/fs/rename` | `POST {from, to}` | Renames or moves a file or folder, creating `to`'s missing parents. Never overwrites: `409` if `to` exists (a case-only rename of the same file on a case-insensitive disk is allowed). `404` if `from` is missing. `400` for the workspace root, anything in or under a `.git` directory (`editablePath`), a path outside the workspace, or moving a folder into itself. Both old and new paths go through `TouchTree`, so the index follows the whole subtree. Emits `tree`. Returns `{ok, path: to}`. |
| `/api/fs/delete` | `POST {path}` | Deletes a file, or a folder and everything in it (`os.RemoveAll`). Same `editablePath` refusals as rename (root, `.git`). `404` if missing. Emits `tree`. Returns `{ok}`. |

After a rename or delete, `treeChanged` evicts the highlight cache (all of it for a folder), closes the LSP document, and calls `Index.TouchTree`; `fsChanged` then refreshes open LSP documents, triggers the git watcher, and emits `tree`.

### Index updates

`Index.TouchPath(rel)` re-stats one path and patches the file list and the parent's children in place (it builds the whole index if it is not ready yet). When the path no longer exists, it also drops every descendant, so a deleted folder takes its subtree with it. `Index.TouchTree(rel)` is the subtree-aware form: it touches `rel` and, when it is a directory, walks it and touches everything below (no symlinks followed, VCS directories skipped, ignored directories listed but not walked), so a folder moved in lands fully indexed.

### The `tree` event

`/api/stream` carries a `tree` event (data `{}`) when the tree changed shape, so the explorer can re-list folders without polling. It is emitted after px0's own `fs/new`, `fs/rename`, `fs/delete`, saving a new file, and `git/discard`, and when the git watcher sees untracked files appear or disappear (it updates the index through `TouchPath` first). It is not emitted for changes to ignored files, in non-git workspaces, or for tracked files appearing from a branch switch. See [Git Integration](git-integration.md) and [File Updates & Reloading](file-reload-and-updates.md).

Handlers are `handleFileText`, `handleFileSave`, `handleFileStat`, `handleFSNew`, `handleFSRename` and `handleFSDelete` in [`server.go`](../../server.go); tests are in [`px0_test.go`](../../px0_test.go) (save, creation, conflict, traversal).

## 2. Frontend

Every file opens straight into Monaco; there is no separate edit mode.

- **Documents** ([`web/src/models.js`](../../web/src/models.js)). `openDoc(path)` reads `/api/file/text` once and creates a Monaco model with the `file` URI scheme, so every editor showing the file (tabs in any group, the editable side of a diff) shares it. The record keeps `mtime`, `eol` (the model's EOL is set to match, so CRLF files save as CRLF), `savedVersion` (the model's alternative version ID at the last save; dirty means it differs) and a reference count. Binary and too-large files get an empty model and open the `binary` viewer instead; paths outside the workspace (absolute paths a language server returned) are read-only.
- **Saving** (`save` in `models.js`). Saves are serialized per document. Each save first applies `files.trimTrailingWhitespace` and `files.insertFinalNewline` as one undoable edit, then posts the model's text with the remembered `mtime`. On `409` a manual save offers **Overwrite** (resend without `mtime`) or **Revert to Disk**; an automatic save flags the conflict and asks the user to save manually. Success updates `mtime` and `savedVersion` to the version actually sent and emits `doc:dirty` and `doc:saved`, which refresh git status, diagnostics, the search results and any Markdown preview of the file. Documents remain alive until an in-flight save finishes.
- **Auto save** ([`autosave.js`](../../web/src/autosave.js), initialized by `actions.js`): `afterDelay` uses a separate timer per document, restarted on edits and rescheduled on Auto Save setting changes. `onFocusChange` responds to editor widget blur, switching active documents, window blur and page visibility. The controller skips closed, disposed, read-only, deleted and conflicted documents, and rechecks eligibility when a timer fires. `save` rechecks the preference after waiting for an in-flight save. **File > Auto Save** and Settings share the persisted `files.autoSave` preference; the Settings form subscribes to changes so an open form stays current.
- **Dirty state.** `isDirty(d)` drives the tab dot, the Open Editors badge, the `●` in the window title, the close prompt (**Save** / **Don't Save**, only when this is the last tab showing the document) and the `beforeunload` guard. **Don't Save** marks the model clean so it is disposed; the next open reads the file again.
- **Revert** re-reads `/api/file/text` and replaces the model's text as one edit (undo history is kept).
- **Changes on disk** are polled with `/api/file/stat`; see [File Updates & Reloading](file-reload-and-updates.md).
- **File operations** ([`web/src/explorer.js`](../../web/src/explorer.js)). New File, New Folder and Rename put an input row into the virtualized tree (`startEdit`); `Enter` posts `/api/fs/new` or `/api/fs/rename`, `Esc` or an empty name cancels, and blur commits. Drag and drop posts `/api/fs/rename` after a confirmation. Delete confirms, posts `/api/fs/delete`, and closes saved tabs under the path. The explorer then reloads its loaded folders and emits `fs:changed` (git status refresh) and, for a rename, `fs:renamed`, which `editors.js` uses to move open tabs to the new path with their unsaved text. **File: New File...** outside the explorer asks for a workspace-relative path in a quick input and posts `/api/fs/new` itself.
